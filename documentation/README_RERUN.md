# R workflow, provenance and limits of reproduction

This directory accompanies the revised manuscript and supplementary document. The current numbering is **T1–T4 and S1–S29**: 33 logical tables. S28 has four panels and S29 has two; the table map therefore may contain 37 CSV files. Figure 1 is an additional artifact, not a table.

## Three different operations

| Operation | Entry point | Inputs | What success establishes |
|---|---|---|---|
| Check the public exports | `R/00_master.R --mode=check_exports` (default) | `documentation/table_map.csv`, mapped table/panel CSV files and preserved R source files | Files exist, their matrices can be read, all 33 table IDs are represented, and archived source bytes match the source index. It is not a numerical comparison with Word or a re-estimation. |
| Generate an artificial example | `R/00_master.R --mode=synthetic` | R base; the preserved synthetic generator | 800 entirely artificial cases and 49 columns, with generator self-checks. These cases do not reproduce any empirical coefficient or table. |
| Extract from the private study archive | `R/00_master.R --mode=private_extract` | Authorized private project, frozen historical reference, historical Word files, existing fitted objects and original SPSS file | Re-extraction of saved model parameters, formatting of saved aggregate predictions, sample descriptive calculations and comparisons with frozen outputs. No SEM, CFA, regression or cross-validation model is fitted by this mode. |

There is deliberately **no automatic training mode**. Full refitting from the original questionnaires is a fourth and separate activity requiring the private archive, a compatible R environment, the original protocols and a reconstructed execution tree. This public source collection is not a claim that the complete historical analysis can be reproduced using only aggregate matrices.

## Public-file checks

From the package root in a terminal:

```sh
Rscript --vanilla R/00_master.R
```

The default output is a new temporary directory, printed on completion. To retain the check record, use a new directory outside this package:

```sh
Rscript --vanilla R/00_master.R --mode=check_exports --output=/absolute/path/new_export_check
```

The map must have `table_id` and `table_file` columns; `table`/`tabla`/`id` and `file`/`csv`/`output_file` are accepted equivalents. Paths are relative to the package root. S28 and S29 panel rows share the canonical table ID. CSV files include their header row; the check reads every cell as text with `header=FALSE` so header labels, asterisks and interval strings are retained. The master writes `source_hash_check.csv`, `export_check.csv`, `mapped_code_check.csv`, `sessionInfo.txt` and `STATUS.txt`. Mapped generator scripts must exist at their declared public paths. Base-R MD5 checks preserved source bytes; SHA-256 provenance is also recorded in `source_index.csv`.

If the map or mapped files are absent, the check stops and reports missing materials. It never substitutes synthetic data for missing empirical outputs.

## Artificial data: explicit demonstration only

```sh
Rscript --vanilla R/00_master.R --mode=synthetic --output=/absolute/path/new_synthetic_example
```

In RStudio:

```r
source("R/00_master.R", encoding = "UTF-8")
run_M2_package("synthetic", output = "/absolute/path/new_synthetic_example")
```

`source()` only defines functions. The master explicitly calls the preserved generator's `exportar_artificial()` function. Its seed is 20261010 and its RNG is Mersenne-Twister / Inversion / Rejection. The original generator checks all three PP items, CSR recoding and fictitious institutions. Its outputs are marked artificial; RDS files generated by this mode are artificial data or hypothetical parameters, not private fitted study objects. If `haven` is already installed, the generator may also write an artificial SAV. No package is installed automatically.

The artificial data use the same variable schema for teaching purposes, but fictional settings and hypothetical distributions. They were not calibrated to the participant sample and do not establish an anonymization or differential-privacy guarantee. Do not insert them into original scripts with empirical N=653/hash checks or describe their results as the manuscript's results.

## Private extraction: exact arguments and historical reference

Only an authorized archive holder can run this mode. Keep the private archive and all output outside a public repository. Use a **new output directory** each time:

```sh
Rscript --vanilla R/00_master.R \
  --mode=private_extract \
  --private-project=/absolute/private/audit/proyecto \
  --private-reference=/absolute/private/audit/referencia \
  --private-word=/absolute/private/audit/Word_referencia \
  --r-library=/absolute/path/to/an/existing/R/library \
  --output=/absolute/private/new_extraction
```

`--r-library` is optional if dependencies are already installed in `.libPaths()`. Paths shown above are placeholders, not resources distributed in the public package. RStudio equivalents are:

```r
source("R/00_master.R", encoding = "UTF-8")
run_M2_package(
  mode = "private_extract",
  private_project = "/absolute/private/audit/proyecto",
  private_reference = "/absolute/private/audit/referencia",
  private_word = "/absolute/private/audit/Word_referencia",
  r_library = "/absolute/path/to/an/existing/R/library",
  output = "/absolute/private/new_extraction"
)
```

The frozen `Word_referencia` contains the historical **three-table manuscript and 21-table supplement**, before adding the new complete-M2 material. Do not point this argument at the revised four-table/29-table documents: the preserved 24-table comparator would correctly reject that contract. The `referencia` tree supplies its frozen table CSVs and `registro/MAPA_TABLAS_CODIGO.csv`; the project tree supplies the original model objects, aggregate outputs and contract JSON.

The private mode performs these operations in order:

1. Calls the unchanged `generar_todas_las_tablas_V3()` function from `R/legacy_table_generator/01_GENERAR_TODAS_LAS_TABLAS_V3.R`, explicitly supplying all paths. It uses `prueba_sin_cv=TRUE`: the historical 175-fit CV branch is disabled. It extracts saved models and formats aggregate exports, then compares the 24 historical tables with the frozen CSV/Word references.
2. Calls `R/extensions/01_extract_complete_M2.R` in a separate `Rscript --vanilla` process. The project path, fresh output and just-generated numerical S7/S8 reference CSV are passed explicitly. This step extracts saved CFA, factor-PSB SEM and correlated-individual-response objects; it reads the authorized SPSS file only to calculate aggregate sample descriptions and audit labels/recoding. It does not fit statistical models.
3. Copies the results into `tables/` using the revised numbering. Historical prediction T3 becomes T4. New T3 is the 18-path MLR individual-response table already represented in historical S7. S1–S21 retain their meaning; S22–S29 extend the evidence. The final publication layer aligns nine text cells with the current Word documents: two M0 Baseline labels in T1/T2, three abbreviated CSR1 labels in S22, and four real line breaks in S22 institution headers. It never changes numerical cells or reads Word to supply results. `publication_presentation_changes.csv` records each before/after value, and `generated_table_map.csv` records each source. The historical CSVs, archived statistical scripts and fitted objects remain unchanged.

The added extractor's third argument is a technical path parameter for the prior S7/S8 numerical reference; it changes no model, coefficient, family or rounding rule. It removes a historical dependence on a particular sibling folder name.

Technical correction tested on 12 October 2026: the master loads the preserved legacy generator using `source(generator, local=env, encoding='UTF-8')`, rather than `sys.source()`. This supplies the `ofile` frame required by that generator's self-location code in a clean RStudio background job, where no `Rscript --file` argument is available. The original generator and statistical procedures remain unchanged. Run background jobs with `importEnv=FALSE` and `exportEnv=""` to avoid importing workspace objects.

- `revision-integral-2026-10-04/analysis/outputs/canonical-full-20261004-02/01_audit/analytic_data.rds` and the preserved P3 fit in `revision-integral-2026-10-04/sensitivities/`.
- `sem-alternativas-2026-10-08/resultados/`: the seven specifications, CFA and SEM, under MLR and WLSMV, with their syntax and aggregate exports.

A missing input causes an error; the master does not fabricate it, impute it from published tables or quietly launch a model to replace it. Original fitted RDS may contain individual data; do not distribute them merely because they are called model objects. Private output directories can also contain private filesystem paths, so review them before sharing anything.

For full historical refitting, reconstruct the private project's **original directory layout** and first inspect the archived scripts' literal path/configuration lines. Several scripts contain absolute study paths or fixed archived output names, and some require earlier private checkpoints or protocols. They are preserved instead of silently patched. Run them in a fresh private working copy with Rscript `--vanilla`, retain logs, do not overwrite the archive, and record any technical path adaptation separately. Source-level completeness is not the same as an independently executable raw-data package. No full refit claim is made for this public release.

## Model, coding and multiplicity distinctions

- T1 is structural SEM fit under seven measurement specifications; S1 is measurement-only CFA fit. They are different fitted objects.
- T2 is selected factor-PSB SEM associations. New T3/S7 use three correlated observed PP responses; neither is the factor-PSB model shown in Figure 1.
- M2 adds `SBL =~ APS2` and `SC =~ APS13`; all retained indicators remain. Four value portraits are separate observed variables.
- Original SPSS CSR1 uses yes=1/no=2; analytical CSR1_bin uses yes=1/no=0. Preserve label-aware recoding rather than subtracting one from the original code.
- Numeric-score MLR, ordinal WLSMV latent responses, CFA total factor correlations and SEM residual correlations are labelled separately.
- Every b has its own b interval and every beta has its own standardised interval. Total-correlation intervals are not fabricated when the extractor returns only point estimates.
- Focal SEM regression tests use their original 21-path unstandardised-p family; the individual model has Holm18 for paths and Holm6 for its joint/equality tests. S29 retains the original **standardised-p Holm16 indirect-family rule**; its companion audit also provides unstandardised-p Holm16 for transparency. These are not substituted for one another.
- Pointwise intervals are not simultaneous Holm-adjusted intervals. Adjustment is within the specified model/family and does not correct model search or all sequential analyses.

## Environment and reproducibility status

Extraction requires `lavaan`, `semTools`, `haven`, `jsonlite` and `digest`. Preserved full-analysis branches additionally use packages identified in `package_requirements.csv`. No `renv.lock` is supplied or implied by this source collection; exact package provenance is recorded in the original/current session information. Current extraction used R 4.6.1, lavaan 0.7-2, haven 2.5.5, jsonlite 2.0.0 and digest 0.6.39. Package number formatting `0.7-2`/`0.7.2` refers to the same installed version. The master records its own actual `sessionInfo()` on every invocation; it does not assert compatibility merely from matching a name.

Original seeds and RNG settings remain in their producer scripts. The grouped baseline uses seed base 20261008 with scenario/repetition offsets, and the regularized procedure retains its own recorded seeds and nested partitions. The extraction branch is deterministic and sets no empirical seed. Saved aggregate prediction means are not newly trained predictions.

Before public sharing, verify the assembled package against the final table map, inspect the final rendered Word files, and exclude original SAV files, participant RDS/RData, per-person records, private fitted objects, individual predictions, fold assignments, tokens and credentials. Public scripts may refer to those files; such references are not permission to publish them. Summary matrices omit some controls and do not encode ordinal thresholds, response distributions or CV partitions, so they cannot reproduce every V3 analysis by themselves.

The public analytical materials are available at https://github.com/lbenitesanchez/sustainability-values-prosociality. The availability of these materials does not imply public access to the original participant records or private fitted objects.
